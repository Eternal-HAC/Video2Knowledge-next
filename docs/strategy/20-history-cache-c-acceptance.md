# G5.1-C 刷新、乱序保护与缓存复测

日期：2026-10-23。范围：[G5.1 合同](17-history-cache-design.md) 的 C 步骤。
当前结论：刷新和浏览器行为门禁已通过；性能方向出现退化，300ms 目标未通过。
原始基准：[schema=2 成对报告](../quality/benchmarks/g51-c-20261023.json)。

## 交互实现

- 新增可选 `GET /api/tasks?refresh=true`，默认 false，原响应和摘要字段不变。
- 显式刷新清空当前进程的历史摘要缓存并重新查询，不修改任务、清单或正文。
- 原刷新按钮保留筛选，从第一页读取；取消未触发的搜索 debounce，避免一次刷新造成两次请求。
- 普通搜索、筛选、加载更多与收藏后的重载不强制清空缓存。
- 请求序号与筛选快照共同决定响应归属，AbortController 只辅助取消。
- 旧搜索、旧追加页及 JSON 读取后迟到的响应均不能更新新列表；更换筛选但 debounce 尚未触发时也不接纳旧结果。
- 只有最新请求可恢复刷新/加载更多按钮及 aria-busy。失败保留已有列表、分页和筛选，给固定中文错误，不回显后端原始异常。
- 追加时筛选已变则退回第一页，不把不同筛选的结果拼接。没有任务提交、付费调用或自动重试。
- 沿用 DESIGN 的现有组件，未重排页面。JS 资源版本更新为 `20261023-4`。

## 基准方法与停止规则

工具增加 `--cache`：新报告 schema=2，六种状态为 direct、cache_empty、hit、refresh、invalidated、capacity。
默认旧测量入口明确绕开列表缓存并标记 bypassed_g5_reference，不能混称为产品缓存查询。
每种状态都执行原四种查询，比较整个响应 hash；计时、Path 方法/读取计数与 tracemalloc 分开。
命中计时记录真实单调时钟起止、hit/miss/eviction 增量及 pure_hit 标记，不暂停或延长 30 秒 TTL。
失效状态执行一次真实 repository 原子替换，内容保持相同；容量状态将内部测试实例限制到规模的四分之一。
所有数据由工具独占创建，旧 G5 报告和输入保留不变。报告不含标题、正文、用户目录或凭据。

本轮请求 100/1,000/10,000 三档，每状态 7 次样本。按合同先检查 1,000 条方向，
缓存命中明显慢于同轮无缓存对照，停止 10,000 条，不把未运行的大规模项写成已通过。
不会自动增加数据库、放宽路径检查、提高 TTL 或扩展缓存容量来改变结论。

这是本机开发观测，系统后台负载和文件缓存未隔离；早期浏览器/专项验证存在重叠。
7 样本 p95 是最大值，不是通用 SLO。元数据计数是 Python Path 方法入口，stat/lstat 可嵌套，不能相加当 OS 调用数。
内存记录为 prepare + query 的 Python 跟踪峰值，不是 RSS 或常驻缓存大小。

### 实际结果

100 与 1,000 条数据的输入 SHA-256 及四种查询的响应 SHA-256 均与旧 G5 after 报告一致。
同轮六种状态之间的响应 hash 也完全相同。四种查询各 7 个计时样本均为真实 TTL 内完整命中，
没有把过期重读算成命中。1,000 条 p95（ms）：

| 查询 | 同轮直接读取 | 完整缓存命中 | 显式刷新 |
|---|---:|---:|---:|
| 默认 | 810.114 | 1189.446 | 2152.194 |
| 组合筛选 | 568.738 | 968.921 | 1694.383 |
| 收藏 | 565.510 | 1073.769 | 1915.087 |
| 第二页 | 675.272 | 1157.120 | 2441.141 |

默认查询命中比同轮直接读取慢约 47%，100 条四种查询也未观察到命中收益。
1,000 条暖态清单 open 从 1,000 降到 0，正文 open 始终为 0，但 Path.resolve 方法入口从
1,000 增到 3,000。该额外路径工作是已证实的成本来源之一；各部分耗时占比仍需单独剖析，
不能用计数直接断言全部退化都由 resolve 导致。冷缓存还要前后双重检查，刷新耗时更高。
这些结果说明当前缓存省读取但整体变慢，性能门禁不通过，不能以旧 G5 的 1011ms 当作本轮对照。

报告完整保留时间样本、容量/字节限制、hit/miss/eviction、元数据与读取次数、Python 分配峰值，
以及 main/repository/cache/基准工具的源码 SHA-256。原始合成数据保留在
`.test-tmp/g51-c-benchmark-20261023/`；没有生成 tasks-10000，停止属于合同要求。

## 当前发布边界与下一候选

缓存仍是未发布工作区中的实验实现。功能测试通过无法抵消性能退化，不能把 G5.1 标为性能优化成功，
也不应据此进入发布。没有提交、推送、构建、安装依赖或外部业务操作。

下一候选应先剖析身份探测、resolve、JSON 投影编解码的成本，再决定安全去重是否足够。
如安全检查保持不变仍无收益，应回退默认列表缓存；不自动引入 SQLite 或后台扫描。
该后续工作独立规划，不在本轮继续扩大实现。
