## 清理与行为锁

1. 先测试旧版字典清单、字幕导入、agent 来源和未知字段；JSON 损坏/非字典读取返回空摘要属于历史浏览的窄兼容行为，写入时必须拒绝覆盖损坏证据。
2. 将重复的清单读改写集中为任务级进程内串行、同目录临时文件原子替换。保留旧函数入口。锁仅覆盖当前单后端进程，不声称支持多个写进程共享工作区。
3. 保留原有无 manifest 的直接调用测试入口；正常提交始终先建立 manifest。拒绝链接/非常规清单。未知字段按顶层合并保留。
4. 显式恢复要求完整有效的转录；缺失或损坏返回明确冲突，不偷偷进入下载/ASR。普通新来源仍按原有流程处理。
5. 新任务记录 parent/ref，继承来源身份，保留原任务收藏与产物，生成新任务不会覆盖旧笔记。
6. 可选 `client_request_id` 只在提交期间去重，记录在原 task.json，无独立数据库。指纹排除 API Key、Cookie 及其哈希。相同 ID/参数重放原任务，参数变化返回 409；删除任务后不再保证重放。显式重新生成使用新 ID。重放不重试失败任务，也不自动付费调用。
7. 失败面板与 MCP 共用恢复摘要，解释已保留的转录、笔记以及重做范围。浏览器不自动重试提交；提交结果不明时使用同一个请求 ID。

## 顺序与验收

- A：仓储行为锁、并发收藏/运行状态/发布写入、损坏证据、原子失败、终态进度保护。
- B：完整转录校验、显式恢复、来源/parent/ref 保留，fake LLM 失败后恢复的下载/ASR 次数为零。
- C：幂等提交，同 ID 同请求并发/重启重放，不同参数 409，无凭据指纹。
- D：网页失败与网络未知态、MCP 参数与恢复摘要，真实浏览器合成数据验证。
- E：针对性与完整 pytest、JS 语法、pip check、diff 审阅，更新验收记录与 snapshot。

审查独立于编写步骤：实现后逐段回读 diff 和实际源码，运行新鲜验证。发现需要架构扩张或新增外部权限时停止该分支并记录，不用兼容回退隐藏问题。
