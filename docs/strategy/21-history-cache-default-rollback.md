# G5.1-D 默认缓存回退

日期：2026-10-24。

## 实施前计划

1. 在独立合成工作区剖析 1,000 条直接读取和暖缓存查询，区分剖析耗时与无插桩延迟。
2. 若收益无法在保留路径安全检查的条件下成立，默认历史列表回到 G5 的每任务单次新鲜读取。
3. 保留缓存模块及显式实验测试入口，不新增产品配置或公开 API；收藏资格、恢复、复用不接缓存。
4. 保留 C 的手动刷新、筛选、分页、乱序隔离和固定安全错误提示。
5. 先补默认列表禁止进入缓存、每次读取 N 个清单且只 resolve N 次的回归测试，再修改实现。
6. 对相同合成数据复测默认路径，核对输入与响应 hash；专项、完整回归和静态检查通过后记录结果。

不降低路径检查，不加数据库、依赖或后台线程，不构建、提交或发布。300ms 目标保持开放。

## 结果

已完成默认回退及源码本地验收，尚未提交或发布。保留此前所有未提交修改。

### 剖析与取舍

原始证据：[插桩剖析](../quality/benchmarks/g51-d-profile-20261024.json)。1,000 条合成任务，
同一处理函数、同一输入、同一响应 hash。default 与 experimental_hit 分别独立预热，
实验查询记录 1,000 hit / 0 miss，未将冷读或 TTL 到期计作命中。

| 插桩观察 | 默认新鲜读取 | 实验暖命中 |
|---|---:|---:|
| cProfile 总时间（秒） | 0.904 | 1.908 |
| Path.resolve 入口 | 1,000 | 3,000 |
| resolve 累计时间（秒） | 0.378 | 1.089 |

累计开销主要集中在 Windows realpath/_getfinalpathname 及缓存快照检查。
计数和累计时间存在调用嵌套，不能相加当独立耗时或系统调用数量。cProfile 有插桩开销，
上表不是 p95、SLO 或跨设备保证。前置探索也观测到同一方向，未将其混入正式延迟样本。
在保留原路径/身份检查的前提下，本轮选择移除默认实验路径的额外工作，不削弱校验尝试追指标。

### 最小实现

- `_list_history_task_record` 默认委托新鲜 `_history_task_record`；仅隔离基准/缓存集成 fixture 显式替换该入口。
- `_cached_history_task_record` 与 `history_cache.py` 保留实验身份，没有用户开关、环境变量、后台线程或新存储。
- 收藏资格、按需恢复、来源复用及产物读取继续走原新鲜路径，不受实验替换影响。
- repository 成功写后/任务删除后的精确失效保留供实验使用；默认列表不向缓存填充任何摘要。
- `refresh=true` 兼容保留；普通查询也新鲜读取，因此同指纹外部变更不再等待实验 TTL。
- C 的刷新按钮、筛选/页码、请求序号、筛选快照、失败安全提示及请求归属规则不变，未改前端代码。
- 默认基准不再偷偷替换 reader，报告明确标为 `production_direct`；`--cache` 才执行六种显式实验状态。

先补的两个 default-cache 禁入测试实际失败，再实施回退。新增第三项证明默认基准使用真实产品 reader，
同时保留原六状态测试，防止停用缓存后把实验命中误测成直接读取。

### 默认路径复测

[默认报告](../quality/benchmarks/g51-d-default-20261024.json)：100 / 1,000 条，每种查询 7 个无插桩计时样本，
分别进行读取计数和 Python 分配观察。全部输入 SHA-256、四种完整响应 SHA-256 与 C 的同规模 direct 对照相同。

| 查询 | 100 条 p95（ms） | 1,000 条 p95（ms） |
|---|---:|---:|
| 默认 | 62.304 | 742.230 |
| 组合筛选 | 64.261 | 774.141 |
| 仅收藏 | 83.105 | 577.604 |

每次读取 N 个清单，不读 notes.md 或 transcript.json；默认回归断言仅 N 次 resolve、缓存条目为零。
7 样本 p95 为最大值，没有控制系统后台负载、OS 文件缓存或防病毒；这些数据不能与 C 跨轮计算配对加速比。
本轮没有重新执行 10,000 条，也没有重复旧 G5 的大规模验收。300ms 参考目标仍未达到。
