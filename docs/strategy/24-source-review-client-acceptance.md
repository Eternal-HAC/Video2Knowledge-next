## 修复：便携版验收可能误认已有实例

旧的 `smoke_portable_beta3.ps1` 和 `smoke_portable_asr.ps1` 扫描 8000–8019，只凭健康接口的产品、版本和 portable 模式挑选服务。若另一个同版本实例已经运行，就可能对它上传合成输入或修改收藏，产生错误验收，也可能污染用户工作区。本轮发现的是脚本选择风险，没有证据表明此前已经误写用户数据。

现在两个脚本复用 `portable_smoke_common.ps1`：从本次启动的 Process 对象和 Windows 进程快照确定父子归属，仅对归属进程监听的 `127.0.0.1:8000–8019` 端口请求健康接口。启动进程退出、根进程缺失、非回环或非归属监听均不选择；查询权限不足时报错，不退回全端口试探。健康接口的产品/版本/模式检查仍保留。

这项保护限定普通本机运行状态；进程快照和 HTTP 连接之间不具备原子性，不承诺抵御恶意本机进程抢占端口。

先新增 11 个失败用例，再修改两个脚本和共享函数。9 个行为案例用真实 PowerShell 执行函数、合成进程/监听记录替代 OS 查询；另外 2 个结构检查确认两条 smoke 均使用新检查。专项连同 Launcher：**41 passed in 8.49s**。测试使用已有 PowerShell 7，没有安装依赖；其他环境需具备该 shell 才能运行这些脚本行为测试。

另做一次真实 Windows 进程/监听验证：启动两个隔离合成 HTTP 服务，版本均相同，非归属服务端口更靠前。实际 CIM 与 TCP 查询只选中指定进程；归属服务收到 1 次健康 GET，另一个收到 0 次。用户 8000 未探测。两个测试进程均由本次持有的子进程句柄结束，未使用全局进程名清理。脚本及临时证据在忽略目录 `.test-tmp/s1-ownership-20261024/`。
