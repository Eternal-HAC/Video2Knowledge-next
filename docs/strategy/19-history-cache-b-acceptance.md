# G5.1-B 历史列表缓存接线验收

日期：2026-10-23。范围：[G5.1 合同](17-history-cache-design.md) 的 B 步骤。
**列表缓存与成功写后失效已本地验收；C 的显式刷新、浏览器乱序验证及性能复测尚未实施。**

## 实现与兼容边界

- `backend/history_cache.py` 持有唯一进程内实例；不持久化、不启动扫描或后台线程。
- `backend/main.py` 提取磁盘白名单投影及共享归并，仅 `/api/tasks` 的列表遍历接入缓存。
- 保留 live result 空字典对磁盘标题的抑制、progress=0、实时计时、严格布尔收藏、平台与 origin 隐藏规则。
- `has_transcript` 每次检查文件存在性；列表不读取 Markdown 或转录正文，不恢复全部历史到 `tasks`。
- 缓存不接纳的旧类型或路径情况通过原 repository reader 处理，保留其路径与文件保护；不截断旧字段。
- 通用清单读取、收藏资格、按需恢复、来源复用、产物读取和导出继续使用原新鲜读取路径。
- `task_repository.update` 在条带写锁内，成功 `os.replace` 后、返回前精确失效；`merge` 复用此路径。
- 锁顺序为 repository → cache。缓存 loader 只调用无写锁的 `read`，不调用 update、merge 或 restore。
- 删除成功后清除对应条目；删除失败保留 live 任务与缓存，不增加删除权限或扩大清理范围。
- 无请求/响应字段变化，无公开 `refresh` 参数，无前端修改。版本仍为 `1.0.0-beta.3`。

容量及新鲜度沿用 A：12,000 项、16 MiB 编码负载、单项 64 KiB、LRU、固定 30 秒期限。
每请求继续发现目录、检查身份、叠加 live 数据和排序。完全同指纹的外部改写可能直到期限后
的下一次查询才反映；涉及收藏资格等操作的判断不使用该缓存。手动刷新将在 C 增加。
编码负载不等于 RSS 上限，路径检查也不构成原子文件系统沙箱或跨进程事务。

## 测试顺序和证据

先新增 29 项接线测试，在接线前实际得到 `7 failed, 22 passed in 3.47s`。
失败证明暖查询仍逐项读清单，产品尚无缓存条目可供精确失效；旧字段优先级用例已通过。
接线后合跑 143 项通过，再补 10 项写入失败、失效粒度、旧类型、损坏回退、固定期限
和非列表 reader 隔离验证。最终专项：

```text
pytest tests/test_history_cache_integration.py tests/test_history_cache.py tests/test_history_performance.py tests/test_task_repository.py -q
153 passed in 6.88s
```

其中接线 39 项、A 核心 78 项、原历史/存储 36 项。旧“无跨请求缓存”测试只改名为
“更新与删除下次查询可见”，原断言保留，没有降低兼容门禁。

具体证据：

- 35 条合成任务，默认、收藏、分页和组合筛选四种查询，冷/暖响应逐项相等；冷读 35 份清单，暖读 0 份；两者笔记/转录正文读取均为 0。
- 人为冻结所有文件指纹，真实收藏接口与 repository runtime 更新仍在返回后的下一查询可见，证明未依赖时间戳碰运气。
- event 协调的真实 repository 读旧值/原子替换竞争中，writer 等待缓存临界区并失效，返回后不会命中旧收藏值。
- change、序列化、replace 失败不写候选缓存，保留原文件，无临时文件残留；成功写入只失效该任务。
- 外部新增、删除、损坏和修复、工作区切换、live 结果/耗时变化及转录存在性变化均有验证。
- 外部相同指纹修改在 29.9 秒仍可命中，在第 30 秒重读，命中不延后期限。
- 非列表 reader 在缓存 read 被替换为失败哨兵时仍可恢复任务及检查来源；损坏转录不再被判为可复用。
- 投影中没有完整 URL、模板指令、日志、正文或清单凭据字段；公开摘要仍只有原 13 个字段。

最终隔离完整回归：**1095 passed, 3 skipped in 70.51s**。
三个跳过仍为 `test_api.py:2012`、`test_asr_process.py:597`、`test_media_retention.py:145`
的既有符号链接权限限制，没有新增 skip。
Python 编译、前端和截图脚本 Node 语法、`pip check`、tracked/new-file whitespace 检查通过。
