建议把产品定位收敛为：**把视频整理成可核对、可重新加工、可带走的个人知识笔记。**

最值得建立的优势，是用户能回答三个问题：这段笔记来自视频哪里？生成失败后已经做的工作还在吗？文件现在在哪里、下次还能找到吗？六个模板和更多平台可以帮助完成这些事，但单独增加它们不足以形成持久差异。

建议先完成未发布开发版的可靠性收口，再做笔记与转录对照、失败后明确复用、轻量阅读器。架构随这三项交付逐步拆分。当前不建议为“显得成熟”引入 React、微服务、向量数据库或第二套 Provider/Pipeline。

## 决策分层

1. 既定约束：一条视频对应一篇 Markdown；本地文件优先；云端发布可选；复用上游；保留 MIT 署名、旧环境变量及协议兼容。
2. 本文推荐：优先可靠性、证据对照、任务恢复、阅读与导出体验。
3. 仍需验证：用户是否真的会核对时间戳、多少任务需要全文搜索、是否需要批量导入、跨平台需求规模。
4. 暂不纳入：账号收藏夹同步、多文件自动拆分、知识图谱、默认 RAG 聊天、移动端原生应用、多用户云服务。

这些设计文件不替换 PRD/DESIGN/DECISIONS。通过某个实施任务后，只将该任务对应决策写入正式基线，避免一次接受整套未来需求。
