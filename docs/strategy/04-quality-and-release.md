# 质量、安全、可观测性与发布设计

状态：混合设计与实施记录。G0–G3 已有对应验收，G4 离线案例、规则工具、人工表、诊断参考及环境/资产对照已实现，见 [G4 验收](14-g4-acceptance.md)。其余阈值和安全/集成方向仍为待执行目标；风险依据见 [研究记录](01-research.md#4-本轮发现的优先审查项)。

## 1. 验收层次

| 层次 | 证明什么 | 不能证明什么 |
|---|---|---|
| 纯函数测试 | 解析、命名、时间计算、模板替换 | 平台可用、模型质量 |
| API/存储集成 | 状态机、产物保存、恢复、权限边界 | 打包子进程与真实界面 |
| 真实浏览器 + fake backend | DOM、请求、焦点、乱序与断连处理 | 真实 Provider 成功 |
| 打包 EXE + 合成输入 + 缓存 ASR | 冻结资源、子进程、离线链路 | 所有模型/平台兼容 |
| 用户授权真实链 | 指定输入/Provider/时间点有效 | 永久稳定或全平台支持 |

现有 721/3 记录来自上一轮，不因纯文档更新重新计数。未来变更运行相关测试与必要回归，不靠“测试数只能上涨”代替用例质量。现有三个链接权限跳过必须有原因，不能新增 skip 掩盖核心安全验证；在具备权限的 Windows CI/测试机补跑重解析点用例。

## 2. 下一轮必须补的故障矩阵

| 场景 | 预期行为 | 验证方法 |
|---|---|---|
| 归档路径指向同目录 `.exe/.lnk/.url` | 文件打开拒绝，允许安全回退任务 Markdown | mock OS open，断言危险目标从未传入 |
| 原始文件/父目录为 symlink/junction | 检查解析前各路径组件，按安全策略拒绝 | 有权限主机真实 link；无权限环境用确定性 stat stub 补逻辑测试 |
| 校验后文件被替换 | 尽可能在打开前复查身份；暴露无法消除的 OS TOCTOU | 受控替换测试；不能宣称绝对消除竞争 |
| `archived_path` 异常、根路径不可解析 | 固定脱敏错误或回退，不泄漏私人路径 | 损坏清单 fixture |
| ASR 无时长/NaN/Infinity/回调倒序 | 不崩溃、不倒退、不显示虚假 ETA | 表驱动纯函数测试 |
| 多 P 混合字幕与 ASR、某页时长未知 | 明确页与阶段进度，旧 ETA 清除 | fake worker 多页事件序列 |
| Task A 慢响应在切换到 B 后返回 | B 的进度/按钮保持正确 | 浏览器 mock 延迟/乱序响应 |
| 服务重启/网络暂断 | 不自动重复提交，历史可恢复 | 中断连接后只查询同 task_id |
| Key 已填但无真实测试 | 仅显示已提供；不宣称鉴权成功 | DOM 状态测试、检查无预调用 |
| 清单收藏/进度/发布同时更新 | 字段都保留、revision 可解释 | 控制时序的存储竞争测试 |
| 飞书创建返回结果不明 | 本地完成保持，标记需核对 | fake CLI 模拟超时/部分成功，禁止自动再创建 |
| 归档失败或磁盘满 | 任务产物可访问，错误与已有输出一致 | 注入写入异常，不删除其他文件 |

## 3. 本机服务边界

2026-10-24 实施更新：[S0 请求边界](23-local-request-security-acceptance.md) 与后续 [真实 HTTP/MCP SDK SSE](24-source-review-client-acceptance.md) 已通过源码本地验收。下面的方案建议保留为原设计依据；已发布 Beta.3 和新候选 EXE 尚未验证本轮安全改动。

已有 loopback 检查与 CSP 应保留，但本机来源检查不等于浏览器请求来源认证。需单独验证 Host、Origin、内容类型与敏感端点，确认恶意站点不能诱导本机服务执行打开文件、凭据变更或任务提交。

建议先做测试再选方案：浏览器有 Origin 时必须匹配允许本机 origin；无 Origin 的 CLI/MCP 兼容不能随意砍掉；远程 Host 或 DNS rebinding 情形需明确拒绝策略。将来若需要会话 token，应同时设计 launcher 注入、MCP 调用和失效机制，不临时给网页单独加一把长期密钥。

截图和 Markdown 继续 DOMPurify/CSP 安全处理；URL 只允许声明的安全协议。原始转录与模型内容都是资料，不能提升为文件路径指令、命令或模型配置。文件打开只允许任务预期 Markdown，不能泛化为任意 shell 调用。

## 4. 数据去向与诊断

用户可理解的说明：字幕获取和本地 ASR 在本机执行；选择云模型时，转录与整理要求发给所选接口；开启飞书后，笔记及引用图片发给飞书。使用本地模型可减少云传输，不能一概宣称所有数据永不离机。

错误对外只展示稳定错误码、阶段、可执行建议。详细异常保留在受控本地日志前也应脱敏；原始异常中可能有 URL 查询参数、任意格式 Key、Cookie、路径、正文片段，单个正则不能保证全部清除。

G4 [诊断合同](../quality/diagnostics.md) 与纯函数参考采用字段白名单：产品版本、运行模式、OS 大版本、Python/依赖版本、阶段耗时、枚举错误码、模型类别和总段数。自由模型名也可能含私人标识，未纳入白名单。原文、标题、URL、路径、命令、环境变量、身份和凭据不导出。实际产品接入、稳定错误码来源及保存前预览尚未实现，不自动上传。

本机计时记录只包含 stage、duration、input duration、model、device class、retry count。用途是估时与性能分析；不默认收集跨用户遥测。费用只能在 Provider 返回 usage 且价格来源明确时估算；未知显示未知，不能按任务数推算真实账单。

## 5. 笔记质量评测集

先建 12 个可公开的合成转录 fixture，每个含 3–8 个需保留信息点：概念课、操作教程、多人访谈、反驳观点、数字/单位、公式、代码、重复口语、中英混合、缺失字幕、长内容尾部、带恶意指令的原文。固定保存输入、预期信息点与检查规则，不用私人媒体。

两条评测轨道：

- 无真实 LLM：用固定模型输出检查渲染、引用范围、Frontmatter、附件、截断处理和失败保留。CI 默认跑此轨。
- 经授权真实 LLM：指定 Provider/模型/参数、样例数、最大调用预算；记录每次请求重试与原始结果，人工对照评分；超预算停止。模型别名漂移时结果只代表当次。

质量表包含：必要信息覆盖率、数字/否定语义错误、无依据补充、可定位引用比例、长文尾段是否保留、格式可读性。引用合法率不代表事实正确；评分不压缩成一个未经验证的“准确率”。建议每个真实样例由人工抽查高风险数字与结论。

模板/提示词改动不得只看一篇漂亮样例。与旧版用相同输入对照，出现事实性回归则暂停推广；先保留旧模板版本与任务快照。

## 6. 性能与可靠性测量

使用相同 fixture 和设备记录冷/暖启动、模型载入、ASR 实时率、各 LLM 阶段耗时、history p95、内存峰值、取消响应。下载/云模型耗时受外部条件影响，不混入纯本地性能结论。

建议门槛：取消 UI 在 1 秒内显示已请求，最终停止时间按实际子进程边界测量；历史 1,000 条暖查询 p95 < 300ms；关键纯本地点击反馈 < 200ms。未达标先分析，不通过隐藏状态或乐观宣称成功达成。

G5 本机参考数据：历史 1,000 条暖态处理函数 p95 从 1755.670ms 降到 1011.433ms，仍未达标。
清单读取减半不等于整个性能门禁通过，启动恢复的单次观察也没有一致改善。
方法与限制见 [G5 验收](16-g5-acceptance.md)；这些数据不证明 HTTP/页面端到端延迟或 EXE 成绩。

## 7. 发布工程

1. 开发允许范围与发布锁定版本分开。先记录已验收环境的版本清单，再评估专用 constraints/lock；锁定过程不授权升级依赖。
2. 核对本地打包 Python 与 workflow Python 当前不同的事实，选定发布基准并分别验证，不假设 Python 3.11 和本地 3.13 行为完全一致。
3. 支持显式手工触发的 workflow 是候选改进。先只读查上次 tag 无 run 的原因（设置、事件、权限），不预设 GitHub 故障。触发规则需校验标签目标/版本。
4. 一次构建产物贯穿验收和上传；记录源码提交、环境、哈希、大小。重新构建即视为不同候选，不能继承旧哈希的验收。
5. 发布闸门：本地自动化 → 浏览器 → 打包离线 smoke → 授权真实链（若本阶段需要）→ push/tag/release → 下载回验。
6. 上游依赖许可证与 bundled vendor 通知清点，提供组件清单。代码签名/SmartScreen 体验可后续评估，涉及证书费用另行决策。
7. 失败只补缺失步骤；不移动标签、不覆盖同名不同哈希资产。发布说明从本版事实生成，不复用失真的“数据不出本机”。

回滚：保留上一版 EXE 与工作区可读性；新增字段可忽略；不自动覆盖用户配置。需要不可逆迁移的版本必须先单独制定备份/恢复合同。
