## 已交付

- `backend/task_repository.py` 集中清单读取、修改和原子替换。固定数量的进程内条带锁覆盖完整读改写；临时文件随机命名，替换失败清理临时文件并保留原件。主模块保留旧清单函数作为薄入口。
- 收藏、运行状态、来源元数据、模板快照、飞书结果使用同一写入口。顶层与运行状态未知扩展字段保留；迟到进度不能覆盖取消终态。
- 读取损坏/非字典清单时，历史浏览仍返回空摘要；写入损坏清单会拒绝覆盖，保留证据。链接、重解析点和多硬链接清单有无 OS 链接权限依赖的模拟测试，不宣称消除了外部进程换路径的竞争。
- 完整校验复用转录的结构、每段文本与有限时间范围，拒绝混杂坏段、负时间、倒置区间、布尔时间、NaN 和错误元数据类型。自动来源预检跳过不可复用转录。
- 显式恢复缺少有效转录时在创建任务前返回 409；执行前丢失转录时明确失败，不回退下载/ASR。来源与原任务冲突时拒绝混用。纯转录历史重启恢复也检查实际有效性。
- 复用任务保存 `parent_task_id` 与 `transcript_ref`，保留 `reused_task_id` 兼容字段，继承来源与字幕导入身份。原任务、原笔记与原收藏不改写；新笔记是独立任务，新任务不自动继承收藏。
- HTTP 笔记/转录入口与 MCP 增加可选 `client_request_id`。同 ID、同参数返回原任务；不同参数返回 409。凭据值与其哈希不进入请求指纹。提交记录与初始清单一次原子写入，任务才进入队列。
- 新增只读 `GET /api/submission/{client_request_id}`，用于确认丢失的提交响应。失败/取消/完成任务状态返回同一个 `recovery` 摘要，MCP 原样保留该语义。
- 网页显示已保留的完整转录与重做说明，只有有效转录才启用“复用转录继续”；新生成使用新请求 ID。提交结果未知时只 GET 查询请求 ID，轮询断线时只重连原任务。没有自动重复 POST。
- 飞书重试可按需恢复旧任务，仍仅发布现有笔记，失败不修改本地完成状态。复用转录时不读取无关的 B 站保存凭据；截图显式启用时仍可能下载预览视频，页面说明这一边界。

## 有界清理结果

- 行为锁：先运行旧 API/取消测试，新增旧版/字幕/agent/未知字段、并发更新、原子失败与损坏证据用例。旧版 fixtures 为基于现有字段的合成代表样例，并对照上游基线的清单写入字段；没有读取用户真实清单。
- 回退分类：历史读坏清单返回空摘要与无 manifest 的直接管线调用为有测试的兼容入口；写入时把坏清单清空、显式恢复失败后偷偷重新下载属于掩盖证据的路径，本轮移除。普通新来源的字幕/ASR 回退继续使用原实现。
- 清理顺序：没有专门删除无关死代码；完成清单 IO 重复移除、错误边界统一、回归增强。没有搬迁路由或另建任务存储架构。
- 改动文件：后端 `task_repository.py`/`main.py`/`mcp_server.py`；前端失败面板的 HTML/JS；仓储/恢复/MCP/前端测试；G2 浏览器脚本及项目文档。G0/G1 原有 CSS、截图脚本、workflow 等 dirty 修改均保留。

## 限制与未验证项

- 仓储锁和提交串行仅适用于当前单后端进程。多 worker/多服务共享工作区尚不支持，不承诺跨进程 exactly-once。
- 幂等映射依附完整 task.json；删除任务、清单损坏、换工作区后无法凭原 ID 保证重放。语义相近但参数形式不同可能返回 409。映射扫描不建索引，历史性能留给 G5 测量。
- 重放只返回原任务，不自动重跑失败任务。服务重启后没有恢复凭据或自动调用模型；用户明确新建才继续。网页请求 ID 只留在当前页面内，刷新后从历史查看，不把请求体或 Key 保存到浏览器。
- “完整转录”指文件结构完整且至少有一段有效文字，不能证明识别准确、覆盖了全部媒体或笔记忠实；质量评价留给 G4。
- 合成 fake LLM 失败后再次生成已验证音频下载/平台读取/ASR 为零，实际 LLM 两次均是测试替身。开启截图可能需要预览视频下载；本轮没有下载媒体或调用真实模型。
- 没有凭据读取、平台登录、飞书实际写入、依赖变更、模型下载或便携版验收。G0 的 Host/Origin 与系统文件打开发布前门禁仍未由 G2 覆盖。
