# 产品方向与交互规格

状态：设计提案。事实依据见 [研究记录](01-research.md)，实施顺序见 [路线图](05-delivery-plan.md)。正式设计基线仍为 [DESIGN.md](../../DESIGN.md)。

## 1. 服务谁，解决什么

首要用户：看课程、技术分享、访谈后，希望将材料放进自己笔记库的个人学习者。次要用户：只需要字幕、或交给 Agent 进一步整理的人。暂不围绕团队协作、视频运营批量搬运或云端企业知识库设计。

核心承诺建议为：**少做重复工作，能核对来源，笔记随时带走。**

| 用户任务 | 当前基础 | 推荐改进 | 成功判据 |
|---|---|---|---|
| 第一次做成一篇笔记 | 模型设置、模板与目的地已有 | 来源先行、简短引导、合成示例体验 | 新用户独立找到输入和开始按钮，知道是否会调用云模型 |
| 等一个长视频完成 | 阶段、时间心跳、取消已有 | 阶段 ETA、服务断连与计算中区别、当前任务固定可达 | 刷新后能找回任务；未知 ETA 不显示倒计时 |
| 对笔记内容有疑问 | 原转录、时间戳已有 | 原文搜索与章节时间范围对照 | 从笔记进入相关转录不超过两次操作 |
| 网络失败后重试 | 转录保留与复用已有 | 明示可复用材料与将重做的步骤 | 有有效转录时重试不触发下载/ASR |
| 找回与使用笔记 | 历史、收藏、多个出口已有 | 阅读目录、结果主操作、外部文件状态 | 能区分本地完成、云发布失败、文件被移动 |

以上是设计目标；当前没有新用户实验或留存数据，不把目标写成已经实现的提升比例。

## 2. 首屏：先给材料，再调整方案

上一轮为了可发现性把模板铺到首屏，手机上长预览又将输入推到下方。推荐改成下面的顺序：

1. 来源：链接 / 本地媒体 / 字幕，输入框与主按钮同一视觉区域。
2. 产物：生成笔记 / 仅转录；说明后者无需笔记模型。
3. 当前方案：模板、详略、保存位置，显示当前值并可直接修改。
4. 模板选择：保持可发现的六模板入口；选中后显示用途，预览默认折叠，由“查看样例”展开。
5. 可选发布与详细设置：默认隐藏不相关项，飞书为附加操作。
6. 当前任务或最近结果优先显示，完整历史作为独立区域/视图。

桌面保留同页快速操作；390px 页面要求初始一屏可见来源输入及开始按钮，展开预览允许自然向下滚动。保留既有 DOM ID、输入值、键盘焦点与模板双向同步。无需引入新前端框架。

## 3. 首次使用与配置状态

引导至多三步：选择产物、确认保存位置、配置所需模型。提供“用合成示例看看效果”，渲染本地固定结果并明确标注示例；不自动创建付费任务。

| 状态 | 建议文案 | 可执行动作 |
|---|---|---|
| Key 为空 | 尚未填写 API Key | 打开对应设置 |
| Key 已填写或已保存 | 已提供 Key，尚未验证连接 | 用户选择是否测试；提交任务不额外预调用 |
| 上次测试通过 | 上次测试通过，时间为… | 保留测试时间；更换端点/模型后失效 |
| 模型缓存检查中 | 正在检查本地模型 | 可继续编辑 |
| 模型不可用 | 本地模型未准备好；有平台字幕时可能不需要转录 | 显式下载/导入入口；仅导入字幕不要求模型 |
| 自定义路径已填 | 已填写保存路径，提交时检查可写性 | 修改路径 |
| 有 pending 检查 | 配置检查中 | 不显示“全部就绪” |

填写状态、静态校验、真实联网验证分开记录；浏览器仅保存非敏感偏好。云模型测试按钮保留明确调用含义。

## 4. 进度与失败交互

显示“当前阶段 + 已用时间 + 已完成材料”。下载可显示已下载字节（上游事件可用时）；Whisper 显示已处理媒体时长；Paraformer/模型加载显示活动状态；LLM 长文可显示已完成片段数。没有总量时用活动指示，不制造匀速进度。

推荐 ETA 文案：“转录预计还需约 2–4 分钟，后续仍需生成笔记”。其范围是经验估算，不称统计置信区间。估计过期、进度长期没有更新或阶段切换时隐藏旧值。首版不提供整项任务的总 ETA。

状态至少区分：等待执行、执行中、正在取消、已取消、失败、完成、页面与服务断开。断开是连接状态，不改写后端任务状态。取消需要后端确认后才能宣称停止。

失败页说明：失败步骤、已经保留的文件、推荐下一步。操作最多两个主选项，例如“用已有转录重新生成”和“下载转录”；技术日志折叠。云发布失败只影响发布卡片，本地笔记仍是完成。

## 5. 轻量阅读器与证据对照

近期先做阅读功能，不直接加入富文本编辑器：

- 从安全渲染后的正文提取标题目录，定位标题，提供笔记内查找。
- “笔记 / 原始转录”切换；宽屏支持并排，窄屏为同一页面的视图切换。
- 保留阅读位置；跳转后允许返回原位置。自动滚动仅在用户明确跟随当前生成时启用。
- 来源信息区展示平台、获取方式（平台字幕/导入字幕/ASR）、实际 ASR 模型、模板与生成配置摘要。
- 时间戳映射先使用现有段范围。点击展示对应原文；有明确支持的平台才拼接跳转 URL，其他平台只打开来源并提示时间。
- 本地媒体已按留存策略删除时，明确提示原媒体不可播放，转录仍可查看；不得为播放静默重下载。

证据对照分两级：第一版只定位章节时间范围；后续才能做观点级引用。时间落在视频内、找到某个段 ID，都不能证明观点真实，UI 不显示“已验证事实”。

## 6. 模板与再生成

保持六个内置模板和一条视频一篇 Markdown。模板卡片显示“适合什么内容、会保留什么、合成样例”。“详略”继续独立于模板，防止模板成为另一套推理/分块配置。

再生成前展示：沿用哪个转录、切换了哪个模板、是否重新调用模型、输出会生成新文件。每次显式再生成是新任务/新产物，不覆盖上一份。为历史记录提供同来源任务分组即可，不要求先建设版本编辑系统。

模板质量改进先通过样例评测：教程应保留前提条件和步骤；访谈需分清谁的观点；知识精华不虚构引述；学习讲义的复习问题不夹带外部答案。不要为补齐空章节增加第二次 LLM 调用。

## 7. 结果与目的地

结果卡分成三块：本地文件、阅读与导出、可选云发布。主操作推荐“打开笔记”，次操作“打开所在文件夹”和“导出”。含图片的 Markdown 下载如果实际返回 ZIP，按钮/提示应写清“Markdown + 附件 ZIP”，避免格式预期落差。

文件在外部被编辑后，预览需要说明显示的是任务原稿还是外部当前版本。近期只展示任务原稿并提供打开外部文件，不自动读回或覆盖用户修改。文件已移动时显示“原保存位置不可用”，允许重新导出新副本，不自动追踪整个磁盘。

Obsidian 是 Markdown 目的地；当前项目不接管 Vault 管理。飞书第一次发布仍显式选择目录；请求结果不明确时提示查远端，避免自动重试重复创建。发布尝试记录与本地完成状态分开。

## 8. 其他维度的优先级

| 方向 | 推荐 | 开启条件 |
|---|---|---|
| 无障碍 | 当前每次改 UI 都验收焦点、键盘、对比度、减少动画 | 无需独立大版本 |
| 界面中英文 | 先整理文案键，中文完成后补英文 | 两套关键流程有维护与截图测试资源 |
| 全文搜索 | 先在当前笔记内搜索；全库搜索晚些做 | 历史规模与实际找不到内容的反馈支持 |
| 批量输入 | 小批明确确认、队列可见、逐条取消 | 单任务恢复和幂等已验收 |
| 浏览器一键发送 | 先评估成熟 Clipper/已有 Agent 入口 | 用户验证粘贴链接确为高频障碍 |
| 幻灯片关键帧/OCR | 独立实验 | 课堂场景的转录确实缺少核心信息；预算/依赖获批 |
| 知识图谱/RAG 问答 | 暂缓 | 先验证用户会反复使用已生成笔记 |
| 自动更新 | 先做好版本提示、校验、手动升级 | 签名、回滚、安装失败恢复俱备后再设计 |
| 移动端/云服务 | 暂缓 | 当前本机服务与文件权限模型需另行设计 |

## 9. 如何验证产品价值

先邀请 5 位目标用户做四项任务：导入字幕成稿、找到原文、模拟模型失败后复用、找到并打开保存文件。记录完成率、卡住步骤、需要解释次数，避免只问“你喜欢吗”。使用合成材料，真实 Provider 测试另行授权。

建议目标：至少 4/5 无帮助找到输入和导出；所有人能区分示例预览和真实生成、配置已填和连接已验证。样本不足以推断总体留存，仅用于发现阻碍。

长期衡量“可带走且可核对的完成任务比例”，拆成保存成功、产物可读、复用成功、引用可定位等可观测指标。文件被打开不等于用户学会了；默认不上传遥测。运行耗时统计留在本机，用户可选择导出脱敏报告。
